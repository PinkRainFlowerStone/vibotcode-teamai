# 幂等不是一把锁

现有积分、会员、商城、供应链和调度代码同时使用业务号、唯一键、状态条件、Redis/Redisson 锁、重试计数和补偿任务。经验表明锁只降低并发窗口，最终正确性仍应落在持久化约束和状态迁移上。

- 请求/回调：稳定业务号或外部单号 + 唯一约束/幂等记录。
- MQ：消息业务键 + 已处理状态或绝对值对齐，允许重复投递。
- Job/批任务：批次状态 + 游标 + 最大重试 + 卡死恢复。
- 库存/预算：原子扣减 + 不足条件 + 数据库镜像/对账。
- 状态机：更新语句携带旧状态，避免人工操作与定时任务互相覆盖。

没有业务键时先补齐契约，不用随机锁 key 掩盖数据模型缺口。
