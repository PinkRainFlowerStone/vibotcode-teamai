# Backend Code Review

1. 读取目标项目 `AGENTS.md`、项目画像、POM、当前 diff 和相邻实现。
2. 先判断服务归属与业务正确性，再检查接口/消息兼容、鉴权、事务、SQL、缓存、锁、幂等、精度、状态机、重试和补偿。
3. 对 Feign、MQ、任务、回调和共享模型列出已知生产者/消费者，确认失败和发布顺序没有被忽略。
4. 核对测试与构建命令是否真实执行；CI 跳过测试时保留验证缺口。
5. 按 `P1`、`P2`、`P3` 输出。每条必须包含文件、行号/范围/符号等精确位置、触发场景、影响和可执行修复方向。
6. `P1` 表示可证明的阻断性正确性、安全、数据或兼容失败；`P2` 表示需要修复的实质风险；`P3` 表示可选改进。不要把无法由代码证明的制度写成问题。
7. 没有问题时明确说明，并列出残余联调、数据或环境风险。
