# Backend Development

## 进入任务

1. 读取目标仓库 `AGENTS.md`、POM、`docs/architecture.md`、`docs/tech-stack.md`、配置键和相邻代码。
2. 从 `references/architecture-profiles.md` 确认项目类型与模块边界。
3. 明确目标、非目标、调用方、数据范围、契约、权限、失败语义和验证方式。
4. 涉及跨服务、MQ、共享模型或数据结构时，先列生产者/消费者、兼容策略、发布顺序和回滚影响。

## 实现

1. 保持 Java 8 和现有依赖版本，复用本项目响应、异常、校验、事务、Mapper/Repository 与公共组件。
2. 把事务控制在本地数据范围；远程调用和异步副作用明确提交前后顺序及补偿路径。
3. 为重复请求、消息重投、任务重跑、回调和并发更新选择业务键、唯一约束、条件更新或受控锁。
4. SQL 参数化并考虑实际数据库方言；金额、积分、库存和预算明确单位与精度。
5. Feign、MQ、缓存和任务变化补齐超时、失败、降级、重试上限、幂等与观测信息。
6. 日志只记录定位所需的脱敏字段和汇总，不打印完整对象、凭证或客户明细。

## 验证

1. 使用 `references/verification-matrix.md` 选择成功、拒绝、重复、超时、并发、部分失败和恢复场景。
2. 先运行最接近改动的测试，再扩大到模块或服务；COLA 项目使用 `-pl <模块> -am` 构建依赖模块。
3. CI 若跳过测试，不能把打包成功描述为测试通过；外部依赖不可用时明确缺口。
4. 交付前检查 diff、配置、依赖、生成物和敏感信息。
