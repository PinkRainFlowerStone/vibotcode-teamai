# Frontend Mini Program Platform APIs

- 仅在确认目标为微信小程序时应用 `wx.*` 约束；其他平台使用其官方能力和当前仓库适配层。
- 网络请求、上传、下载和 Socket 必须复用仓库现有请求/鉴权/错误抽象。合法域名、HTTPS、超时、并发、重试和环境选择以当前平台配置及仓库契约为准，不依赖开发者工具中的跳过校验选项。
- `wx.login` 返回的是临时登录凭证。凭证应按现有链路发送给服务端换取业务登录态，不得被当作长期身份、跨会话复用或记录到日志；`appSecret`、服务端密钥和签名私钥不得进入小程序端。
- storage 只保存有明确用途、生命周期和清理策略的数据。敏感身份、个人信息、支付上下文和高风险业务状态不得因方便而持久化；键名、序列化和迁移沿用仓库现有封装。
- 调用需要授权、隐私同意或声明的能力时，配置、真实 API 调用、用户告知、同意/拒绝路径和降级行为必须一致。手机号、位置、相册、摄像头、麦克风、联系人等敏感能力不得以静默失败替代拒绝处理。
- 支付、订阅消息、分享、扫码、定位、媒体、文件系统、上传下载等高风险 API 需要核对前后端职责、幂等/重复点击、取消/失败、页面卸载和真实设备行为。客户端不得承担应由服务端完成的密钥保管、金额裁决、签名或最终授权。
- 新增平台 API 时核对仓库目标基础库，并在需要时使用 `wx.canIUse` 或仓库已有兼容层提供检测与回退。不要把开发者工具可用等同于全部用户环境可用。
- Promise 与 callback 选择遵循目标基础库和仓库封装；无论形式如何，都要收口成功、失败、取消、超时、重复触发和页面/组件销毁后的竞态。
