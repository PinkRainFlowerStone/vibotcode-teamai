# Frontend Mini Program Performance And Verification

- 评估 `setData` 的更新路径、频率和载荷，避免整棵对象回传、滚动回调高频同步、长列表一次性渲染和已经卸载页面的状态写入。
- 图片、媒体、长列表和大组件应按真实场景治理加载、占位、失败、释放和复用；不在缺少测量时宣称性能提升或回归。
- 主包、分包、独立分包、预下载和懒加载调整必须基于当前 `app.json`、目标基础库和发布链验证。平台数值上限应在实施时查阅当前官方文档，不固化到团队规则。
- 开发版、体验版和正式版可能存在环境、权限、域名、数据和 `envVersion` 差异。版本切换、灰度和回滚策略沿用仓库与发布平台现有约定。
- 只运行并声明仓库实际存在的 lint、类型检查、测试和构建命令。`miniprogram-ci`、自动化工具或组件模拟器只有在仓库已安装、配置并有脚本时才可作为验证依据。
- 开发者工具编译、预览、上传、质量分析和真机验证按改动风险选择。支付、授权、隐私、分享、扫码、定位、媒体、文件、Socket、性能和版本兼容等平台行为不能仅由静态检查证明。
- 输出必须区分已运行命令、开发者工具验证、真机/体验版验证和未执行项；未执行的平台验证作为残余风险披露。
