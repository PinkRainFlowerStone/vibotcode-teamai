# Frontend Mini Program WebView Bridge

仅当目标小程序自身的配置和代码证明其使用原生 `<web-view>` 承载 H5 业务时应用本规则。这是可选运行形态之一，不是小程序默认架构；不得因为团队参考模板采用 WebView 而要求业务使用、保留或迁移到 WebView。

- 业务域名、服务器域名、环境和目标 H5 入口必须同时符合微信公众平台配置与仓库配置。开发者工具能打开页面不等于正式环境已完成域名校验。
- 页面查询参数、扫码/分享入口和 H5 下发的跳转地址均视为外部输入。进入 `<web-view>`、跨页面或跨小程序前，应按仓库契约校验允许的 origin、路径、协议和参数，避免把任意 URL 直接变成开放重定向入口。
- URL、小程序路径和 JSON 参数需要明确编码层级，并在发送端与接收端成对处理。不要用多次 `encodeURIComponent`/`decodeURIComponent` 或无约束字符串拼接掩盖参数所有权。
- `bindmessage`/`postMessage` 是跨运行时消息边界。按允许的消息类型和字段验证 `detail.data`，再用于分享标题、链接、图片、导航或身份操作；不得默认信任 H5 消息内容。
- 微信临时登录凭证、业务 token、授权码和用户标识只能交给明确受信的 H5/服务端链路，并遵循用途、时效和清理契约。避免在 URL、全局变量、storage 或日志中扩大暴露范围。
- 原生页、WebView、H5 授权页和目标小程序之间的进入、返回、重定向、重新进入和失败兜底需要有可追踪协议。不要依赖页面栈偶然状态或通用 storage 键完成跨页面握手。
- WebView 不能替代原生授权、隐私、支付、定位、分享和真实设备验证。H5 与原生两侧都必须处理拒绝、超时、重复触发和环境差异。
- H5 参数名、页面路径、接口字段、域名白名单和 storage 键均由目标仓库决定；单个模板中的命名不得提升为团队标准。
