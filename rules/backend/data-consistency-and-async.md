# Data Consistency And Async Work

- 本地事务只承诺本地数据一致性；远程调用、MQ 和文件操作不得被当作全局事务。跨系统部分成功必须有状态、补偿、对账或人工处置路径。
- 请求重试、MQ 重投、XXL-JOB 重跑、定时任务并发和第三方回调必须按稳定业务键幂等，并使用唯一约束、条件更新、状态机或受控锁形成最终防线。
- 金额、积分、库存、预算、资格、权益、结算和状态迁移必须明确精度、单位、原子性、并发条件和失败回滚；禁止隐式浮点换算。
- Redis/Redisson 锁必须有明确 key 作用域、等待/租约策略，并只由持有者释放；锁不能替代数据库约束和幂等记录。
- 缓存写后失效、预热或重建应与事务提交顺序一致；重建覆盖在线数据前校验版本或权威数据源。
- 批处理必须有范围、分页/游标、成功/失败/跳过统计、重试上限和恢复入口；不得无边界重放或循环内刷完整明细日志。
- MQ 消息和任务参数变化需兼容旧生产者/消费者；重复、乱序、超时、部分失败和补偿重跑都应进入验证范围。
