# Component And Style Boundaries

- 页面负责接口编排、路由联动和状态组织；页面私有组件放在页面附近，跨业务复用后再进入共享组件目录。
- 可复用组件优先受控，默认通过 `props + emit` 通信，不在子组件中隐式修改父级状态。
- 组件输入显式命名、输出事件表达动作；输入输出格式保持稳定，接口数据转换由边界清晰的一层负责。
- 表单、表格、弹窗等多重职责明显混杂，或单文件接近 600 行且已影响阅读时，按业务职责拆分；行数只作为信号，不为拆分而拆分。
- 简单布局、间距和字号可使用项目已配置的 UnoCSS；复杂状态和第三方组件覆盖使用局部 SCSS。
- 组件样式默认 scoped；深层覆盖使用 `:deep()`，不使用 `>>>`、`/deep/` 或 `::v-deep`。
- 全局样式只承载 reset、布局、主题变量、UI 框架全局覆盖和真正通用的 class；页面样式不得写入全局入口。
- 复用现有主题变量、组件、图标和 `src/assets` 资源，不引入第二套 UI、图标或样式体系。
- 修改公共组件时检查调用方影响，并同步更新已有组件文档。
