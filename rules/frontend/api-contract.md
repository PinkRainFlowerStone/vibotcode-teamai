# Frontend API Contract

- API 调用必须经过当前仓库现有 request 封装和 API 模块；函数命名、目录和客户端实例以仓库事实为准，不在组件内创建平行请求层。
- 只使用需求、接口文档或现有代码明确给出的字段和 request options。
- 禁止为未知字段写 `a || b || c`、别名映射、默认推断或隐式兼容。
- 高风险参数变更先记录 `field -> source`，特别是积分规则、策略画布、商城下单、支付和权限场景。
- 异步操作显式管理 loading，并在 `finally` 中复位；失败后的数据、空态、禁用和重复提交行为必须明确，不能依赖偶然残留状态。
- 路由、按钮、请求的权限或身份语义沿用目标项目已有来源，不发明新的权限 key、游客态或资格判断链路。
- 页面私有状态留在组件；只有确需跨页面共享的状态进入 Pinia。
