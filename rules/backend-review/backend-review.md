# Backend Review Gate

后端审查先报告问题，再给结论。按以下顺序检查：

1. 服务归属、业务状态和边界是否正确。
2. 接口、DTO、Feign、消息、任务、表结构与共享模型是否向后兼容。
3. 鉴权、权限、站点/租户隔离、敏感数据和开放接口安全是否完整。
4. 事务、远程调用、缓存、锁、MQ、任务重跑和补偿是否形成可恢复的一致性方案。
5. 金额、积分、库存、预算、资格、权益、结算和状态迁移是否处理精度与并发。
6. SQL、分页、批量、索引、日志和外部调用是否存在性能或可观测性风险。
7. 验证是否覆盖成功、拒绝、重复、超时、部分失败和恢复路径。

结论使用 `P1`、`P2`、`P3`。每条正式问题必须包含文件、行号/范围/符号等精确位置、触发场景、影响和可执行修复方向；无法由代码证明的制度不得写成缺陷。没有正式问题时仍需列出未执行验证和残余联调、数据或环境风险。
