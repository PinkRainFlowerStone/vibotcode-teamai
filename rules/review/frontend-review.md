# VibotCode Frontend Review Gate

- 使用 `frontend-code-review` Skill 作为审查流程和输出协议的唯一来源。
- Workflow 的非空 `scope` 输入或用户显式审查范围优先，并覆盖默认基线；未指定时按 `origin/pre...HEAD` 审查已提交增量，缺少可用 `pre` 基线时再询问用户。
- Workflow 的非空 `requirements`、`context` 输入用于需求、验收标准、API 映射、PR 描述和风险说明；两者均为空时继续规范与运行风险审查，并披露无法完整验证需求行为的缺口。
- 先读取目标仓库 `AGENTS.md`、平台规则、平台文档、实际脚本/清单和必要的相邻代码，再判断变更。
- 单一运行端审查只加载一个平台画像：PC Web、移动 Web 或小程序。跨平台审查必须按目标分别标注，不能混用 DOM、路由、组件、存储、权限或兼容约束。
- 只报告由增量引入、修改、变为可达或明显恶化的问题，不把历史债务转成当前变更问题。
- 结论统一使用 `MustFix`、`ShouldFix`、`NiceToHave`。正式问题必须包含置信度、位置、增量归属、规则编号、证据、影响和聚焦的修复方向。
- 低可信度但重要的外部契约问题放入待确认事项，不作为正式问题；没有发现时明确说明残余验证或上下文缺口。
- 格式化和可由现有静态工具可靠发现的问题交给项目工具，只报告与本次改动行直接相关的真实诊断或质量门禁缺失。
